## 关于 `k230/` 里的参考实现

`config.py` / `compat.py` / `geometry.py` / `ballistics.py` / `tracker.py`
是我在理解你需求之前先写下的实现，属于"答案册"。

**建议：先自己写，写不出来或写完想对照再看。** 直接抄的后果是第 3 天
出了问题你没法判断是自己的逻辑错还是抄来的代码错。

其中 `config.py` 可以当作参数清单来用（里面每个参数为什么存在都写了注释），
这一份看了收益最大、损失最小。

参考实现里有几个值得注意的设计选择（你自己写的时候可以自己想一遍为什么要这样）：

1. **为什么 `geometry.cam_to_body` 只是交换轴和符号**：相机系（右/下/前）到机体系
   （前/左/上）是一个纯轴置换，不需要矩阵；把矩阵省掉，出错概率也小。
2. **为什么弹道要建表**：MicroPython 每帧迭代求解要 2~5 ms，启动时算一次表只要 10 ms。
3. **为什么滤波在世界系做**：云台自己在转，像素和角度都不是目标的真实运动。
4. **为什么 3 个 1 维滤波而不是 6×6 矩阵**：世界系三轴噪声近似解耦，省 90% 算力。

## 待你确认的三件事（影响后面所有细节）

1. **板子型号**：CanMV-K230 官方板 / 立创·庐山派 / 其他？—— 决定 sensor id 和 UART 引脚。
2. **电控协议**：波特率、帧格式、谁发云台角、单位是 rad 还是度。
3. **相机**：GC2093 还是 OV5647，能否手动曝光（自瞄必须能）。

把这三个信息补上，加上你**自己写的代码**（贴文本或放进 workspace 告诉我路径），
我就能按 `docs/03` 第 7 节那张表逐条 review。
