# 三天落地计划（按 checkpoint 走，不按时间走）

每个 checkpoint 都写死了**验收标准**。达不到就不许进下一个——自瞄这种系统，
带着一个坏层往上叠，第 3 天你会花一整天找不到问题在哪。

假设：每天 ~10 小时有效工作，你会 YOLO 训练和 OpenCV，K230/串口/电控都是新的。

---

## 第 0 天晚上（1~2 小时，决定第 1 天顺不顺）

| 事项 | 产出 | 备注 |
|---|---|---|
| 装 CanMV IDE K230，烧最新固件，连上板子 | IDE 里能读到 `/sdcard` | 固件版本记下来，写进 README |
| 跑官方 `yolov8n_detection` 例子 | 屏幕/IDE 上看到框 | 这一步就能暴露 90% 的环境问题 |
| 找电控队友确认**串口协议**：波特率、帧格式、谁发什么 | 一页纸的协议，双方签字确认 | 见 `docs/03_调试与标定.md` 第 4 节 |
| 确认云台零位约定：yaw 正方向、pitch 正方向、单位 | 一致的口径 | 这一条错了，第 2 天全部返工 |

**今晚只干这四件。别写代码。**

## Day 1 —— 目标：板子上能看到"装甲板"，且串口能通

### C1-1 相机取帧跑通（2h）

任务：写 `camera.py`，把 sensor 配成 `640x360 @60fps`，`main.py` 里循环取帧并
`print(frame.shape)`。

验收：
- 连续打印 100 帧不报错，shape 是 `(3, 360, 640)`
- 让画面正立（`hmirror`/`vflip` 调对——**这一步决定了后面所有角度的符号**）
- 帧率 ≥ 50fps

卡住了看：`docs/03` 第 2 节 现象表第 1~4 行。

### C1-2 自己的模型上板（3h）

任务：训一个**单类 `armor`** 的 yolov8n，`imgsz=320`，导 onnx → nncase → kmodel，
板上跑起来。

为什么单类：3 天时间里，区分大小装甲板/编号/红蓝是**纯亏本买卖**。
先能打中，再谈打谁。单类的模型还更快、更不容易漏检。

验收：
- kmodel 能在板上加载（打印模型输入输出 shape）
- 对真实装甲板，`conf>0.35` 时 1m/3m/5m 都能稳定检出，连续 100 帧漏检 < 5 帧
- 帧率 ≥ 30fps（含推理）

卡住了看：`docs/03` 第 2 节第 5~7 行（最常见是 kmodel 输入尺寸/类别顺序/量化）。

### C1-3 检测结果"边界化"（1h）

任务：写 `detector.py`，把 `libs.YOLO` 的返回统一成
`(x1, y1, x2, y2, score, cls)`。**第一件事是打印一帧原始返回**，
确认它到底是 `xyxy` 还是 `xywh`。

验收：屏幕上画的框和装甲板边缘基本吻合（差 1~2 像素无所谓）。

> 这一小时非常值：不同固件版本 `libs.YOLO` 的返回格式不一样，
> 网上的代码抄过来框会歪，90% 的人卡在这。

### C1-4 串口打通（2h）

任务：`uart_link.py`。**顺序绝对不能反**：

1. 先只发常量：每 100ms 发一帧固定的 `d_yaw=0, d_pitch=0`，电控那边能收到、校验通过
2. 再让电控发数据上来，你打印 `yaw/pitch/v`
3. 最后才接算法

验收：
- 电控能正确解析你的帧（让它把收到的原始字节打印出来对一遍）
- 你收到的 yaw/pitch 和你用手掰云台的方向一致（往左掰 yaw 变大？还是变小？记下来）
- 连续跑 5 分钟不断帧、不丢帧

卡住了看：`docs/03` 第 2 节第 8~10 行。

**Day 1 结束时的状态：板上能稳定输出装甲板 bbox，串口双向通。算法一行没写，这是对的。**

## Day 2 —— 目标：云台跟着装甲板转（不开火）

### C2-1 相机内参 + 测距（2h）

任务：写 `geometry.armor_to_cam()`，用 bbox 高度反推距离。

标定方法（不用棋盘格，用卷尺更快）：见 `docs/03` 第 5.1 节。

验收：
- 卷尺量 1.0 / 2.0 / 3.0 / 5.0 m，屏幕上打印的距离误差 **< 5%**（3m 处 ±15cm）
- 8m 处误差会到 10~15%，这是 640x360 的物理极限，接受它（原因见 `docs/02` 第 3 节）

卡住了看：`docs/02` 第 3 节 + `docs/03` 第 2 节第 11~13 行。

### C2-2 坐标变换（3h）—— 最容易翻车的一小时

任务：`geometry.cam_to_world / world_to_cam / dir_to_angles`。

**不要上板调**。在电脑上写个 10 行的测试：给一组 (yaw, pitch, 相机系点)，
正反变换回来，误差必须 < 1e-9；再验证"光轴方向"等于 `(cosθcosψ, cosθsinψ, sinθ)`。

验收（板上）：
- 云台不动，把装甲板从画面左边移到右边，打印的 `世界系 y 坐标` 单调变化
- 云台左右转 30°，同一个静止目标的世界系坐标基本不变（漂移 < 5cm）

这条验收标准是整套系统的地基。**过不了就别往下走。**

### C2-3 云台跟随（3h）

任务：`logic.step()` 里先实现"傻瓜版"：取离画面中心最近的一个框，
算出 `d_yaw, d_pitch` 直接发给电控。**这一版不要滤波、不要预测、不要弹道。**

验收：
- 手拿装甲板在 2~4m 移动，云台能跟上，肉眼看不到明显滞后/抖动
- 静止目标时，`d_yaw` 收敛到 ±0.003 rad 以内（屏幕上会小幅跳，正常）
- 云台不抖、不啸叫（抖 → 见 `docs/03` 第 2 节第 14~16 行）

**Day 2 结束：云台会追装甲板了。这就是"自瞄"的 80%。**

## Day 3 —— 目标：打中静止靶 → 打中移动靶

### C3-1 弹道（2h）

任务：`ballistics.py`。第 1 天先只做重力（`k=0`），能打中 3m 固定靶就加阻力。

验收（打靶，不是看数值）：
- 3m 固定靶：10 发中 7 发以上
- 5m 固定靶：加弹道补偿后，落点比不加时高，且不越过靶心上方太多
- 记录成表（`docs/03` 第 5.3 节模板），后面调 `k` 全靠它

### C3-2 滤波 + 预测（2h）

任务：`tracker.py`，世界系 3 状态可解耦 → 3 个 1 维 CV 卡尔曼。

验收（对比实验，必须做）：
- 同样的横向移动靶：关预测 vs 开预测，各打 10 发
- 开预测命中率必须明显上升（+30% 以上），否则你的延迟符号/数值是错的

### C3-3 开火策略 + 抗干扰（2h）

验收：
- 静止时不会乱开火（对齐 + 连续 3 帧 + 距离门限）
- 目标被遮挡 0.5s 再出现，云台不乱甩（`MAX_MISS` 逻辑）
- 画面里有 2 个装甲板时，不会在两个之间来回跳（加目标切换迟滞）

### C3-4 收尾（2h）

- 关掉所有 `print`，量最终帧率
- 写 `README.md`：怎么烧、怎么改参数、遇到 X 怎么办
- 录像留证

## 如果进度落后，按这个顺序砍

1. **砍预测**（C3-2）→ 打静止靶也能得不少分
2. **砍阻力**（`k=0`，只算重力）
3. **砍多目标**（画面里只跟离中心最近的一个）
4. **砍开火**（只让云台跟，扣扳机由人/电控判断）
5. ~~砍测距~~ **绝对不能砍**——没有距离就没有弹道，等于没自瞄

## 三条保命原则

1. **每次只改一个变量，改完立刻测**。同时改 `Q` 和 `LATENCY`，你永远不知道是谁生效了。
2. **任何时候都要有"回退到上一版能用"的代码**（`main_work.py` + `main_dev.py` 分开）。
3. **晚上 11 点后不要重构**。这时候写的代码，第二天你自己都不认识。
