# 调试与调参手册（这份最值得反复看）

自瞄调试的痛苦，99% 来自"同时有 5 个地方可能错，而我只有一个现象"。
解决办法只有一个：**把系统切成能独立验证的五层，从下往上，一层一层锁死。**

---

## 1. 五层调试金字塔

| 层 | 你会观测到什么 | 验收标准 | 这一层坏了的表现 |
|---|---|---|---|
| L1 取帧 | `frame.shape`、帧率 | 形状对、≥50fps、画面正立 | 后面全乱，且看不出原因 |
| L2 检测 | bbox 数值 + 画框 | 框贴合、漏检率<5% | 距离乱跳、云台抽搐 |
| L3 几何 | 距离(米)、世界系坐标 | 卷尺误差<5%、静止目标世界坐标稳定 | 云台转对了但越远越偏 |
| L4 控制 | `d_yaw/d_pitch`、开火标志 | 静止时收敛、移动时跟得住 | 反向、抖动、来回摆 |
| L5 联调 | 靶面落点 | 命中率 | 一切都对，就是打不中 |

**铁律：L(n) 没验收，绝不动 L(n+1)。** 你已经有 OpenCV 基础，L1/L2 会比较快，
真正吃时间的是 L3——那也是我建议你在电脑上先写完的部分。

### L1 怎么观测
```python
print(frame.shape)          # 必须是 (3, 360, 640)
```
再加一个帧率计数器（每 30 帧打印一次平均耗时）：

```python
t_last = time.ticks_ms()
n = 0
while True:
    frame = cam.get()
    n += 1
    if n % 30 == 0:
        now = time.ticks_ms()
        print("fps=%.1f" % (30000.0 / time.ticks_diff(now, t_last)))
        t_last = now
```

### L2 怎么观测
打印**前 3 个框的原始数值**，不要只打印个数：

```python
print([(int(d[0]), int(d[1]), int(d[2]), int(d[3]), round(d[4], 2)) for d in dets[:3]])
```
把装甲板放在画面正中、已知距离，手算一下 bbox 高度对不对（见第 5.1 节）。

### L3 怎么观测
把中间量打出来，一行就够，这是你后面所有调参的唯一依据：

```python
print("d=%.2f p=(%.2f,%.2f,%.2f) yaw=%.3f pitch=%.3f" % (dist, p[0], p[1], p[2], yaw, pitch))
```

### L4 怎么观测
```python
print("dyaw=%+.4f dpitch=%+.4f fire=%d" % (d_yaw, d_pitch, fire))
```
`d_yaw` 的**符号**是第一个要确认的东西：让目标往左移，`d_yaw` 应该变大
（如果你的约定是"左为正"）。反了就是坐标系约定问题，**别在 PID 里加负号糊过去**。

## 2. 现象 → 病因速查表

| # | 现象 | 最可能的原因 | 先查什么 |
|---|---|---|---|
| 1 | 取帧报错/黑屏 | sensor id 不对、引脚复用冲突 | 先跑官方例子确认固件没问题 |
| 2 | 画面上下颠倒/镜像 | `hmirror`/`vflip` 没调 | 调完再往下做，否则角度符号全反 |
| 3 | 帧率只有 10~15fps | 分辨率太高、开着屏幕、`print` 太多 | 关 `DEBUG_DRAW`、关 `print`、降到 640x360 |
| 4 | 帧率越跑越低 | 内存碎片（MicroPython 常见） | 循环里别 new 大对象，定时 `gc.collect()` |
| 5 | 检测不到 | kmodel 输入尺寸/归一化参数不对 | 打印 model 输入 shape，对比训练 imgsz |
| 6 | 框位置错位、偏移 | `libs.YOLO` 返回是 xywh 不是 xyxy | 打印一帧原始 res，人工对一遍 |
| 7 | 类别下标越界 | `LABELS` 顺序和训练时不同 | 打印 `len(res)` 和 `res[0]` |
| 8 | 串口完全收不到 | TX/RX 接反、波特率、FPIOA 没配 | USB-TTL 直接抓线，看有没有电平跳变 |
| 9 | 收到乱码 | 字节序、CRC 算法不一致、帧头不同 | 双方先只发一个固定常量对拍 |
| 10 | 云台抽一下停一下 | 串口丢帧/解析越界 | 加帧头+CRC，打印坏帧计数 |
| 11 | 距离整体偏大/偏小 | `fy` 不准、bbox 标注松紧 | 三点法标定（5.1） |
| 12 | 距离跳变剧烈 | bbox 高度只有 7~10 px | 加大 R、或提高分辨率 |
| 13 | 越远越偏向一侧 | 相机与枪口不同轴 | `YAW_OFFSET` 近似补偿（5.2） |
| 14 | 云台反向转 | 坐标系约定不一致 | 看 `d_yaw` 符号，别用负号掩盖 |
| 15 | 云台高频抖动 | R 太小 / Q 太大 / 曝光太长 | 静止目标下看 `std(d_yaw)` |
| 16 | 云台来回摆（低频） | 目标切换没迟滞、或预测过冲 | 关预测试一次；加切换迟滞 |
| 17 | 静止准、移动偏同一侧 | 延迟补偿不对 | `LATENCY_MS`（5.4） |
| 18 | 3m 准、5m 打高 | 阻力没标定 | `k`（5.3） |
| 19 | 全部同方向偏一点 | 机械安装/零位 | 常量偏置，几 mrad 就够 |
| 20 | 白天好晚上差 | 曝光/增益自动跳变 | 全部手动固定 |

**用法**：先在第 1 列找到你的现象，第 3 列就是你要加的那一行 print。
不要凭直觉改代码。

## 3. 三个能救命的调试习惯

### 3.1 录制-回放（最有价值的一条）

K230 有 SD 卡，把每一帧的 `dets + 收到的 gimbal` 写成一行文本存下来，
拿回电脑上用 `tools/sim_logic.py` 重放。**这样调参不用去靶场。**

板上：
```python
f = open("/sdcard/log/run01.csv", "a")
f.write("%d,%.4f,%.4f,%.2f" % (t_ms, yaw, pitch, v))
for d in dets:
    f.write(",%.1f,%.1f,%.1f,%.1f,%.2f" % (d[0], d[1], d[2], d[3], d[4]))
f.write("\n")
```
注意：写文件会明显掉帧，**只在专门跑数据的时候开**，别在比赛代码里留。

电脑上重放的好处：
- 同一段数据可以反复跑，改 Q/R/LATENCY 看效果，秒级迭代
- 你能画出「d_yaw 时间曲线」，抖不抖一眼就看出来，比现场看云台直观十倍

### 3.2 单一变量原则

每次只改一个参数，改完立刻测同一段（静止/移动各 10 发）。
改了 `Q` 和 `LATENCY` 然后成绩变好，你并不知道是哪个起作用，下次换场地就崩。

建议在 `logs/tuning.md` 里记一行：`日期 | 改了什么 | 从多少到多少 | 结果`。

### 3.3 REPL 分组自检

CanMV IDE 连上后，REPL 里可以单独验每一层，不用跑整个 main：

```python
>>> import geometry
>>> geometry.self_check()          # 纯数学，必须第一个通过
>>> import ballistics
>>> s = ballistics.BallisticSolver(25.0, 0.02)
>>> print(s.solve_pitch(5.0, 0.0)) # 应该是 0.045 左右(2.6°)
```

「纯算法一定要能在 REPL 里 3 秒钟验一次」——这是分层设计给调试带来的最大红利。

## 4. 和电控联调的规矩

顺序错了必翻车，严格按这个来：

1. **先把协议写成一张纸**：波特率、帧头、长度、CRC 算法、每个字段的类型/单位/正方向。
   双方各留一份，签字（真的，写进 `docs/`）。
2. **只发常量**：视觉每 100 ms 发 `d_yaw=0, d_pitch=0`，电控打印收到的原始字节。
   字节对上了，才说明协议实现一致。
3. **电控发、视觉收**：云台角、弹速。你打印出来，用手掰云台确认正负号。
4. **闭环但限幅**：电控那边先把 `d_yaw` 限到 ±0.1 rad，错了也打不到人。
5. **最后才接真实算法**。

常见协议坑：
- **单位**：你发 rad，他以为度 → 云台转 57 倍。协议里必须写清 `rad`。
- **正方向**：你"向左为正"，他"向右为正" → 反向。
- **增量 vs 绝对**：强烈建议**发增量**（`d_yaw`），这样零位不一致也不影响。
- **字节序**：STM32 和 K230 都是小端，但 `struct` 一定要写 `'<'`。
- **帧同步**：一定要帧头 + 长度 + CRC。裸发 float 迟早错位一字节，然后云台疯狂乱转。

## 5. 参数标定（每个参数只用一个实验定）

### 5.1 内参 / 测距（30 分钟，收益最大）

不用棋盘格。用卷尺 + 装甲板：

1. 把装甲板（或一张 12.5cm 高的纸）贴在墙上，卷尺量出相机到它的距离 `z`。
2. 在**目标正对相机**时，取 30 帧 bbox 高度，求平均 `h_mean = y2 - y1`。
3. 算 `D = z × h_mean`。这个 `D = fy × H` 才是真正能辨识的量
   （`fy` 和 `H` 是耦合的，你没法分开标定，也没必要分开）。
4. 换 1.5 / 2 / 3 / 4 m 各做一次，得到 4 个 `D`。取平均写进 config：
   `CAM_FY = D_mean / ARMOR_H`。
5. 看这 4 个 `D` 的离散度：如果随距离**单调下降**，说明 bbox 在远处被低估
   （标注偏紧或目标太小时框被压扁），把 `ARMOR_H_SCALE` 设成 `D_mean/D_near`
   这种经验比例。离散度 < 5% 就可以收工。

> 判定标准：3 m 处距离误差 < 5%（±15 cm）。做不到，别进 L3。

### 5.2 角度偏置（10 分钟）

让云台对准 3 m 处固定靶的**中心**，看打印的 `d_yaw`、`d_pitch` 稳定在多少。
那个残差就是 `YAW_OFFSET / PITCH_OFFSET`（符号取反）。
注意：这个偏置只能吃掉"零位+安装"的常量误差，**吃不了不同距离的误差**（那是不同轴造成的）。

### 5.3 阻力系数 k（1 小时，打靶）

1. 固定靶放在 3 / 5 / 7 m，每个距离打 10 发，记录落点相对靶心的**垂直偏差**（cm）。
2. 平均偏差 `e` 换算成"还差多少仰角"：`Δθ = atan(e / L)`。
3. 电脑上跑：
   ```python
   from ballistics import BallisticSolver
   for k in (0.0, 0.005, 0.010, 0.015, 0.020, 0.030, 0.040):
       s = BallisticSolver(v0, k)
       print(k, [round(s.solve_pitch(L, 0.0), 5) for L in (3, 5, 7)])
   ```
   把打印出来的仰角和"实测需要的仰角"比，选误差最小的 `k`。
4. **前提**：`v0` 必须是实测初速（测速仪或电控给的标称值）。`k` 和 `v0` 会互相
   吸收误差——`v0` 填错，`k` 会把自己调成一个畸形的值，换距离就崩。

判定：如果几个距离的残差方向不一致（3 m 偏低、7 m 偏高），说明不是 k 的问题，
是第 5.1 节的距离不准，回去重新标。

### 5.4 延迟 LATENCY_MS（30 分钟，必须有移动靶）

实验：让靶以**恒定速度**横向移动（用滑轨或人匀速走），打 10 发，看落点：

| 落点 | 含义 | 动作 |
|---|---|---|
| 分布在靶**前方** | 预测过头 | `LATENCY_MS` 减小 5~10 |
| 分布在靶**后方** | 补得不够 | `LATENCY_MS` 增大 5~10 |
| 前后都有、很散 | 不是延迟问题，是抖动 | 回去调 R，或降帧率波动 |

量化：`Δt = 平均偏差(m) / 靶速(m/s)`。例如 1.5 m/s 的靶、平均偏后 0.12 m → 少补了 80 ms。

### 5.5 R 和 Q（用日志算，不要拍脑袋）

**R** 用观测噪声估：目标静止，采集 100 帧距离 `z`，算标准差 `σ_z`，
`R_POS ≈ σ_z²`。典型 640x360、3 m 处 σ≈0.05 m → `R ≈ 2.5e-3`。

**Q** 只影响跟随速度，没有"正确值"，按 `docs/02` 第 5 节的顺序调：
先 R（静止不抖）→ 再 Q（移动不滞后）。

### 5.6 开火阈值（数据驱动）

静止目标下采 200 帧 `d_yaw`，算 `σ`。阈值取 `3σ`（保证 99.7% 的"正常抖动"不会误触发），
再叠加"连续 3 帧"的条件。这样你的阈值有依据，换环境也能快速重算。

## 7. 我帮你 review 代码时会重点看的 12 个点

你把代码发我（贴文本或写进 workspace 告诉我路径），我按这张表逐条挑错：

1. **单位**：`d_yaw` 是 rad 还是度？`dist` 是米还是毫米？字段名有没有带单位后缀。
2. **符号**：`d_yaw`、`pitch` 的正方向是否和电控一致；是不是靠加负号糊过去的。
3. **坐标原点**：测距点是相机光心，弹道起算点是枪口吗？混用会产生随距离增长的误差。
4. **dt 的来源**：是用 `ticks_diff` 真实时间，还是硬编码 `1/60`？帧率一抖滤波就废。
5. **滤波初始化**：第一次观测时速度方差给够大没有？否则前 10 帧全是错的。
6. **异常路径**：检测为空时，是返回旧值、还是返回 None、还是直接除零崩溃。
7. **丢帧策略**：`MAX_MISS` 之后有没有 `reset()`，还是让卡尔曼自己乱飘。
8. **循环里的内存分配**：有没有每帧 `list.append` 大量对象、字符串拼接（MicroPython 会碎片化）。
9. **串口阻塞**：`uart.read()` 是在等固定长度吗？会不会卡死主循环。
10. **`print` 与 `sleep`**：正式代码里还有没有；`sleep_ms` 会不会拖慢帧率。
11. **开火条件**：是否只有"角度对齐"，没有距离门限/稳定帧/目标有效性。
12. **参数是否集中**：有没有魔法数字散落在逻辑里。

一次只解决一类问题，我们按 L1→L5 的顺序过。
