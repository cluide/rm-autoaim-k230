# 知识要点：自瞄这条流水线，每一步在解决什么问题

先看全景。**每个箭头都是一个"信任边界"，也是你调试时要切开的地方。**

```
 相机曝光 → 取帧 → YOLO 推理 → bbox → 测距(3D) → 坐标变换 → 滤波/预测
   │                            │        │           │           │
 2~4ms食物                      │        │      世界系坐标    云台角速度补偿
                           检测层的坑  距离是最大的误差源      预测要吃掉延迟
                                │        │           │           │
                                └────────┴───────────┴───────────┘
                                              ↓
                                    弹道仰角 + 目标选择 + 开火判定
                                              ↓
                                     串口(增量角) → 电控PID → 云台
```

---

## 1. 相机：为什么自瞄必须手动调曝光

这一条 90% 的教程不提，但它是"静止能打中、对抗打不中"的头号原因。

云台追目标时转速轻松到 180°/s ~ 400°/s（3.1 ~ 7 rad/s）。曝光 1 ms，目标在
5 m 处移动 `ω·d·t = 7 × 5 × 0.001 = 3.5 cm`。默认自动曝光在室内常给 15~30 ms，
那就是 **5~10 cm 的拖影**——装甲板直接糊成一片，YOLO 的框会变宽、变小、跳过。

做法：

```python
sensor.set_auto_exposure(False, exposure_us=3000)   # 3ms 起步，先保证能看清
sensor.set_auto_gain(False, gain=?)                 # 固定增益，否则噪声会闪
```
代价是画面变暗。所以**补光/换大光圈镜头**是硬件前提，不是软件能救的。

验收：用手快速甩云台，暂停后看单帧画面，装甲板边缘应该是清晰的。
如果你能看出"两个影子"，说明曝光还是太长。

## 2. 检测层：为什么第 1 天只训单类

- 单类没有"类间混淆"——大小装甲板在远处都是几个像素，分错类只会让你更早失败。
- 单类模型更小更快，K230 上同样 320 输入能多出几 ms 预算。
- 你现有的 YOLO 技能完全够：把 `names` 改成 `{0: 'armor'}`，数据里大/小装甲板混着标，
  `imgsz=320`，`yolov8n`，训练 100~150 epoch 就够。

**bbox 的坑**（会直接毁掉测距，见第 3 节）：

- 标注框贴太紧 → 距离偏远；松一圈 → 偏近。所以需要 `ARMOR_H_SCALE` 这个全局修正系数。
- 目标只有 7 个像素高时，框的高度误差 ±1px 就是 ±14% 的距离误差。**这是物理极限，认了它。**

## 3. 测距：为什么"用高度"而不是"用宽度"，以及它的极限在哪

单目测距的公式只有一个：

```
z = fy · H / h_px        z: 距离(m)  fy: 焦距(像素)  H: 装甲板真实高度(m)  h_px: bbox 高度(像素)
```

**为什么用高度不用宽度**：装甲板绕竖轴旋转时，宽度会被透视压缩
`W_见 = W·cos(φ)`，φ 是偏转角。你用宽度算距离，目标一转头距离就跳。
高度不受这个影响（装甲板不会前后翻），所以高度是稳的那个。

但它的误差是**平方级放大**的，把误差传播算出来就明白了：

```
Δz/z = -Δh/h                     (1 像素误差带来的相对距离误差)
h = fy·H/z
```

取 `fy=460, H=0.125 m`：

| 真实距离 | 图上高度 h_px | 1px 误差 → 距离误差 |
|---|---|---|
| 1 m | 57.5 px | 1.7% → 1.7 cm |
| 2 m | 28.8 px | 3.5% → 7 cm |
| 3 m | 19.2 px | 5.2% → 16 cm |
| 5 m | 11.5 px | 8.7% → 43 cm |
| 8 m | 7.2 px | 13.9% → 1.1 m |

结论，记牢：

1. **640x360 上，5 m 以外的距离只能当"差不多"用**，8 m 基本靠猜。
2. 所以算法必须**用滤波器把多帧的距离平均起来**（噪声 ∝ 1/√N）。
3. 所以第 3 天优先保证**近距离命中率**，别在 8 m 上死磕。
4. 真要远距离，唯一出路是提高分辨率（1280x720，帧率掉一半）或上四点 PnP + 亚像素角点。

对比一下角度精度：`1 px → atan(1/460) = 2.2 mrad = 0.125°`，在 5 m 处是 1.1 cm。
**角度靠像素非常准，距离靠像素非常不准。** 这句话能帮你想通很多现象。

## 4. 坐标系：唯一必须背下来的东西

```
世界系 W：x 前, y 左, z 上   yaw 绕 z 向左为正   pitch 抬头为正
机体系 B：x 前, y 左, z 上（云台 yaw 轴对齐）
相机系 C：x 右, y 下, z 光轴向前（OpenCV 约定）
```

转换两步：

```
x_B =  z_C          x_W = cψ·cθ·x_B - sψ·y_B - cψ·sθ·z_B
y_B = -x_C    ->    y_W = sψ·cθ·x_B + cψ·y_B - sψ·sθ·z_B
z_B = -y_C          z_W = sθ ·x_B  +  0 ·y_B + cθ ·z_B
```
（ψ = yaw，θ = pitch，c/s = cos/sin）

**两个必须立刻验证的性质**（这是你的单元测试）：

1. 正反变换往返误差 < 1e-9。
2. 相机光轴 `(0,0,1)_C` 变到世界系，必须等于 `(cosθcosψ, cosθsinψ, sinθ)`。

第 2 条错了，说明 pitch 的符号或者旋转顺序错了。**别靠肉眼看云台猜**，
云台一动你就分不清了。用这条数学恒等式，5 秒钟定位。

**为什么要转到世界系**：因为云台自己在动。云台转 10°，静止目标的像素位置变了几百像素，
但它在世界里的位置没变。你在"像素/角度"上做滤波，等于把云台的主动运动当成目标的运动，
预测必然错。这是新手和第二名之间最大的分水岭。

## 5. 滤波：Q 和 R 到底在调什么

你在世界系跑 3 个解耦的 1 维匀速模型（`[位置, 速度]`），每个轴：

```
预测: p += v·dt,   P = F·P·Fᵀ + Q
更新: K = P/(P+R),  p += K·(z-p),  v += K·(z-p)·(二阶项)
```

用大白话讲这两个参数：

- **R（观测噪声）大** → "我不太信这次的测量" → 平滑、抗抖，但**滞后**。
  抖动主要来自 bbox 像素级的跳变（±1~2px）。R 的量级就取这个：
  `R ≈ (0.05 m)² = 2.5e-3`（对应 5m 处 ±1px 的距离噪声约 5cm）。
- **Q（过程噪声）大** → "我猜目标会突然变速" → 跟得快，但**抖**。

调法（顺序不能反）：

1. 目标**静止**，只调 R：从 `1e-3` 往大调到云台不再抖。指标看 `std(d_yaw)`，
   目标应在 0.001~0.002 rad 以内。
2. 目标**横向匀速移动**，只调 Q：从 `0.5` 往大调到不滞后，正好"贴住"就行。

一个残酷的事实：R 和 Q 不能同时最优，这就是**平滑 vs 滞后**的权衡。
所以真正解决问题的不是调参，是**降低观测噪声**（曝光、分辨率、置信度阈值）。

## 6. 预测：把"延迟"吃掉

延迟不是抽象概念，它是一笔一笔能算的账（60fps 下）：

| 环节 | 典型耗时 |
|---|---|
| 曝光 + 出图 | 3 ~ 8 ms |
| 取帧 + 送 ai2d | 2 ~ 5 ms |
| KPU 推理（yolov8n@320） | 8 ~ 15 ms |
| 后处理 + NMS + 解析 | 2 ~ 5 ms |
| 算法（测距+滤波+弹道） | 1 ~ 3 ms |
| 串口 115200 发 20 字节 | ~1.7 ms |
| 电控解析 + PID 响应 | 10 ~ 30 ms |
| **合计** | **30 ~ 65 ms** |

目标以 2 m/s 横移，50 ms 就是 **10 cm**——比装甲板还宽。所以预测不是"高级功能"，
是**必需品**。而且注意：**电控的响应延迟也算在里面**，你不能只补视觉那段。

预测公式（一次迭代就够）：

```
t_fire ≈ now + LATENCY + tof(L)
p_aim  = p_track + v · (t_fire - t_last)
θ_aim  = atan2(p_aim.z, |p_aim.xy|)
d_pitch = θ_aim - pitch_now
```

`tof` 是弹丸飞行时间（5 m/25 m·s⁻¹ ≈ 0.2 s，比视觉延迟还大！）。
**用了弹道的飞行时间，你就已经比大多数新手强了。**

调试要点（第 3 天必做的对比实验）：

- 关预测打 10 发、开预测打 10 发，记录落点在目标"运动方向的哪一侧"。
- 落点总在**前方** → 预测过头 → 减小 `LATENCY_MS`。
- 落点总在**后方** → 预测不足 → 增大 `LATENCY_MS`。
- 量化：`Δt = 偏差 / 靶速`。靶速 1.5 m/s、落点偏后 0.15 m → 少补了 100 ms。

## 7. 弹道：为什么"先重力，后阻力"

纯重力闭式解（`k=0`）：

```
tanθ = (v² - √(v⁴ - g(gL² + 2hv²))) / (gL)
```

`v=25, L=5`：`t = 0.2 s`，下落 `0.5·g·t² = 0.196 m`，仰角 `2.25°`。

但 RM 的 17 mm 弹丸是泡沫球，阻力很大，`v(t)` 会明显衰减，真实下落更多。
`k = 0.02 /m` 时：

| 距离 | 纯重力仰角 | 含阻力仰角 | 差 |
|---|---|---|---|
| 3 m | 1.35° | 1.5° | 0.15° |
| 5 m | 2.25° | 2.6° | 0.35° |
| 8 m | 3.59° | 4.15° | 0.56° |

在 8 m 处 0.56° ≈ 7.8 cm，**一发打飞**。所以阻力必须标定（方法见 `docs/03` 5.3）。

**为什么用"查表"而不是"每帧迭代"**：K230 是 MicroPython，每帧做 20 次二分 ×
30 步积分要 2~5 ms，白吃帧率。启动时算一张 24 点的落点表（~10 ms），
之后每帧只做一次插值（~0.05 ms），精度差 0.1 mrad 以内，可以忽略。

## 8. 开火：别把"对准"等同于"能打中"

最简单的版本：`|d_yaw| < th` 且 `|d_pitch| < th` 且 `dist ∈ [1, 8]` 且连续 3 帧成立。

但真正的自瞄要考虑：

- **稳定帧**：单帧对准就开火，会打在云台过冲的瞬间。
- **距离门限**：太近（<1 m）弹道补偿无意义且可能打到自己人；太远（>8 m）测距不可信。
- **目标丢失**：`MAX_MISS` 帧内还继续预测，超过就停火（否则会追着空气打）。
- **单发 vs 连发**：RM 上连发（burst）命中率通常更高，但要跟电控约定好频率，
  视觉只给 `fire` 标志位，**节奏由电控掌握**，别在视觉里做定时器。

## 9. 目标选择：三天内做个"够用"的

画面里通常有 1~3 个装甲板。够用的策略：

```
score = -角度差 - 距离惩罚 + 当前目标加成
优先：正在跟的目标 > 离准星近的 > 近处大的
再加"切换迟滞"：新目标要比当前目标明显更好(比如好 20%)才换
```

没有迟滞，云台会在两个目标之间疯狂来回摆——这是 RM 赛场上最尴尬的画面。

**进阶（不做也行）**：小陀螺目标（自转）应该瞄"旋转中心"而不是"装甲板表面"，
需要 `p_center = p_plate - R·n`，其中 `n` 是装甲板外法线，要有偏航角估计。
3 天里别碰，做了也调不出来。

## 10. 系统性误差清单（排错时逐条对照）

| 误差源 | 表现 | 修法 |
|---|---|---|
| 曝光过长 | 移动目标框抖动、变宽 | 手动短曝光 + 补光 |
| 内参不准 | 距离整体偏差、随距离线性偏 | 标定 fy |
| bbox 标注松紧 | 距离有固定比例偏移 | `ARMOR_H_SCALE` |
| 相机/枪口不同轴 | 近处准、远处偏（角度误差） | `YAW_OFFSET/PITCH_OFFSET` 或真实平移量 |
| 零位/机械安装 | 所有距离同方向偏 | 常量偏置 |
| 帧率不稳 | 偶发打偏 | 关 print、关屏幕、降分辨率 |
| 电控响应慢 | 移动靶全偏在同一侧 | 预测里加 latency |
| 串口丢帧 | 云台抽搐 | 帧头 + CRC + 接收缓冲 |
