## 1. 公告原文的要求（这是唯一的判据）

> **三．视觉（算法）组**
> 1. 掌握 Linux 系统使用，熟悉 **C++ 或 Python** 编程，具有良好的数学思维与程序设计能力；
> 2. 了解机器人学基础，掌握 **ROS 2** 的基本概念，能够进行**机器人仿真平台搭建**；
> 3. 了解**图像处理、深度学习、SLAM** 等领域关键算法的原理，能够将算法模型**迁移应用**到实际问题上；
> 4. 有相关**项目经历、竞赛经验**者优先。

把它翻译成"要什么"：

| 条款 | 真正在考什么 | 你现在的状态 |
|---|---|---|
| 1 | 能在 Linux 里活着；Python 够用（C++不是硬门槛） | 🟡 Windows 为主，Linux 没手感 |
| 2 | ROS 2 三个概念 + 能跑起仿真 | 🔴 完全没碰 |
| 3 | 知道算法**为什么**有效，能把它接到真问题上 | 🟡 会训 YOLO、会 OpenCV，但没"接到真问题"过 |
| 4 | 有一个能讲 10 分钟的项目 | 🔴 空 |

**结论：你的短板不是 YOLO，是 Linux + ROS 2 + "一个讲得清的项目"。**

## 2. 明确建议（三条，带取舍）

### 建议一：Python 路线完全成立，不要现在去学 C++

公告写的是"C++ **或** Python"。RM 视觉里 Python 大量用于训练、工具链、算法验证；
ROS 2 也有官方的 `rclpy`。**现在学 C++ 是拿最贵的成本换最小的边际收益。**
但要知道一个事实：队里性能敏感的部分（实时推理、串口）可能用 C++，
所以你的定位应该是"**Python 能把算法跑通、能量化、能讲明白**"，而不是"我要重写整个框架"。

### 建议二：把"门票"和"作品"分开，先买票

- **门票 = Linux + ROS 2 + Git**（公告第 1、2 条，也是入队后每天都在用的东西）
- **作品 = 自瞄**（第 3、4 条，"把算法迁移到真问题"的唯一证据）

顺序必须是**先门票后作品**。原因很现实：面试时你说"我用 K230 做了自瞄"，
对方下一句一定是"你这个节点怎么组织的/怎么和电控通信的/怎么标定的"。
如果没 ROS 2 和 Linux 的手感，这些你都答不圆，作品反而暴露短板。

### 建议三：自瞄项目"降规格"，但要"升深度"

3 天做一个能跑的自瞄，对你现在的状态是**不可能高质量完成的**（K230 环境 + 电控联调
至少要一周，还要等板子、等队友）。建议改成：

- 把 `rm_autoaim_k230` 拆成两段：**先在 PC 上用摄像头 + OpenCV 做完几何/滤波/弹道**
  （这段你完全能独立完成，而且能做得很扎实），
- 再决定要不要上 K230（上板只是"换个取帧和加速"，算法一行不用改——这正是分层设计的意义）。

而且面试时**"PC 上跑通、误差能算、参数有标定依据"比"板子上跑起来了但说不清为什么"值钱得多。**

### 不要碰的东西（重要）

- **SLAM**：第 3 条提到了，但那是哨兵/导航方向。自瞄方向三年都用不上，现在学是纯浪费。
- **C++ 模板/多线程优化**：等你能把 Python 版本跑到 30fps 再说。
- **自己从零写 YOLO 后处理/训练框架**：用现成的。你的时间该花在"误差从哪来"。

## 3. 术语速查（你"不清楚"的大概是这些）

| 词 | 一句话 |
|---|---|
| 装甲板 | 车身上带灯条的识别板，小 135×125 mm、大 230×125 mm，四角有灯 |
| 自瞄 | 相机找到装甲板 → 算出枪该抬多少度 → 串口告诉电控 → 云台转过去 |
| 云台 | 两个电机（yaw 水平 / pitch 俯仰）带枪管，自瞄的输出对象 |
| 发射机构 | 摩擦轮 + 拨弹，初速 15~30 m/s，**初速是弹道解算的输入** |
| 能量机关 | 另一类视觉任务：识别旋转的九宫格并"打符"，与自瞄是两条技术线 |
| 前哨站 / 基地 | 固定目标，装甲板大，用来练远距离和弹道 |
| 电控 | 队友，负责 STM32、电机、PID、和你的串口通信 |
| ROS 2 | 机器人中间件：把"相机节点/检测节点/解算节点"用 topic 连起来 |
| 节点 / topic | 节点＝一个进程；topic＝带名字的广播频道 |
| 标定 | 用已知距离/角度反推相机参数，是所有精度的前提 |

## 4. 任务清单（按优先级，勾着做）

标记：**P0 = 门票，必须** · P1 = 作品核心 · P2 = 加分

### 第 1 周：Linux 与工程习惯（P0）

| 编号 | 任务 | 验收标准 | 产出 |
|---|---|---|---|
| T1 | 装 Ubuntu 22.04 双系统（不行就 WSL2 + Ubuntu 22.04） | 连续 4 小时在 Linux 里写代码不切回 Windows | 一篇装机笔记（含踩的坑） |
| T2 | 命令行 20 个命令（`ls cd cp mv rm chmod ps top grep find pipe > >> df du`）+ ssh | 不看教程完成：建用户、装包、压缩解压、查进程、传文件 | 一份 cheat sheet（自己敲一遍再写） |
| T3 | Git：commit / branch / merge / PR | 自己的仓库有 5 次有意义提交；给别人的项目提过 1 个 PR | GitHub 链接 |
| T4 | Python 工程化：venv、`requirements.txt`、`argparse`、`logging` | 把你现在的 YOLO 推理脚本改成带命令行参数和日志、拆成 3 个文件 | 重构前后的对比 |

### 第 2 周：ROS 2 最小闭环（P0，最像真实 RM 视觉架构）

| 编号 | 任务 | 验收标准 | 产出 |
|---|---|---|---|
| T5 | 装 ROS 2 Humble，跑通 talker / listener / turtlesim | 能口头讲清 node / topic / service / parameter 的区别 | 3 行笔记 + 一张 ROS 图截图 |
| T6 | 写 `rclpy` 节点：摄像头取帧 → `publish` 图像 | `ros2 topic hz` 稳定 ≥ 15Hz，`rqt_image_view` 能看到画面 | 节点代码 |
| T7 | 写 `rclpy` 节点：订阅图像 → 跑 YOLO → 发布检测结果（自定义 msg） | 端到端 < 100ms；`ros2 topic echo` 能看到框 | 节点代码 + msg 定义 |
| T8 | 用 launch 文件 + 参数把 T6/T7 串起来 | **一条命令**启动全流程 | launch 文件 |
| T9 | 跑通一个仿真环境（Gazebo 或 turtlesim 级别的就行） | 能在仿真里看到机器人模型，能改一个参数看效果变化 | 截图 + 说明 |

> T6~T8 就是 RM 视觉的真实骨架：相机节点 / 检测节点 / 解算节点 / 串口节点。
> 你把这个跑通，"ROS 2 基本概念"这一条就硬了。

### 第 3 周：自瞄核心（P1，全在电脑上，不用板子）

| 编号 | 任务 | 验收标准 |

## 5. 面试/考核必问的 5 个问题（提前把答案写成数字）

1. 从曝光到云台动，**总延迟多少毫秒**？你怎么测出来的？
2. 距离怎么算的？**误差多大**？为什么用高度不用宽度？
3. 为什么在**世界系**滤波？云台自己也转，你怎么把云台的运动扣掉？
4. 弹道补偿怎么做的？阻力系数 `k` 是**怎么标定**的？
5. 开火条件是什么？为什么这样**不会误开火**？

> 你的回答里如果有"大约""差不多"，就减分；有"3m 处 ±16cm，因为 bbox 高度只有 19 像素，
> 1 像素误差就是 5%"这种，就加分。**量化能力是视觉组最看重的。**
